# ZeroFold

**Fold information to its minimum useful state. Unfold only what intelligence requires.**

ZeroFold is a conservation and memory layer for LLM systems. It sits between
a conversation and the model calls around it, doing three jobs:

1. **Remembers durably, cheaply.** When messages age out of active context,
   ZeroFold distills anything durable — facts, decisions, preferences,
   constraints — into small, deduplicated, provenance-tracked records
   instead of letting them disappear.
2. **Proves memory earns its keep.** Every stored record tracks what it cost
   to produce and how much it has saved on reuse. Nothing gets promoted to
   long-term storage on vibes; promotion follows explicit rules and ROI.
3. **Gives a router a capability floor, not a guess.** Before a request goes
   out, ZeroFold estimates the minimum model tier the task actually needs,
   so a router can pick the cheapest model that clears that bar instead of
   defaulting to the biggest one "to be safe."

ZeroFold **never calls a model itself**. It hands back atoms, decisions, and
scores; a host application supplies the model calls and the routing and
billing logic around them. That's a deliberate boundary: ZeroFold is the
conservation/memory engine, not the router. [SubtracToken](https://github.com/michaelchaves-dev/subtractoken-router)
is an example of the router half — it owns pricing, provider fallback, and
economics; ZeroFold owns the memory and conservation decisions a router can
plug into. See [`examples/router_integration_sketch.py`](examples/router_integration_sketch.py)
for what that integration looks like end to end.

The full design record this package implements is in
[`docs/spec.html`](docs/spec.html) (generated by
[`scripts/generate_spec.py`](scripts/generate_spec.py)) — read it for the
complete rationale behind each piece below.

## The name family

| Name | What it is | Module |
|---|---|---|
| **Zero Atoms** | The canonical subject/predicate/object fact shape everything else is built from | `zerofold.atoms` |
| **Zero Codec** | Canonicalization and the two hashes every atom needs (`source_hash`, `object_id`) | `zerofold.codec` |
| **Zero Language** | A compact, reference-based intermediate representation — interns repeated terms so nothing is stored twice | `zerofold.language` |
| **Zero Conveyor** | Turns messages falling out of active context into atoms instead of discarding them | `zerofold.conveyor` |
| **Zero Ledger** | The ROI/payback accounting layer over CNS — decides promotion, tracks whether memory is worth its cost | `zerofold.cns.ledger` |
| **Zero Supervisor** | The public facade: `intake()`, `evict()`, `outbound()` | `zerofold.supervisor` |
| **CNS** | The persistent truth/state store everything above reads and writes to | `zerofold.cns.store` |

Supporting modules that don't get their own "Zero" name but do the load-bearing
work: `zerofold.bloom` + `zerofold.similarity` (candidate generation for
dedup), `zerofold.relevance` + `zerofold.distiller` (deterministic extraction),
`zerofold.fidelity` (the compression-trust gate), `zerofold.dedup` (ties bloom
+ similarity + polarity into one decision), `zerofold.complexity` (the
routing floor), and `zerofold.contracts` / `zerofold.outbound` (response
validation).

## Quick start

```python
import asyncio
from zerofold import CNSStore, ZeroSupervisor, contract_from_intent

async def main():
    store = CNSStore("cns.db")   # ":memory:" for a scratch/test store
    await store.connect()
    supervisor = ZeroSupervisor(store)
    namespace = "customer-42"    # scope memory per tenant/customer/session

    messages = [
        {"role": "user", "content": "Always keep your replies under 100 words."},
    ]

    # Before routing: get a model-tier floor + any durable context to inject.
    enrichment = await supervisor.intake(namespace, messages, intent="chat")
    print(enrichment.min_quality_tier, enrichment.context_snippet)

    # ... send `messages` (+ injected context) to whatever model you chose ...
    response_text = "Sure, I will keep it brief."

    # After the response: validate it against an output contract.
    contract = contract_from_intent("chat", recommended_max_tokens=200)
    result = supervisor.outbound(response_text, contract)
    print(result.passed, result.violations)

    # When messages age out of the active context window: don't just drop them.
    report = await supervisor.evict(namespace, messages)
    print(report)  # atoms_created / atoms_reinforced / atoms_superseded

    await store.close()

asyncio.run(main())
```

Run the fuller version of this with `python3 examples/router_integration_sketch.py`.

## How a message becomes memory

```
messages aging out of context
        │
        ▼
  relevance gate (deterministic, no model call)
        │  discards pleasantries, retries, dead ends
        ▼
  Step Zero Distiller (regex/heuristic, no model call)
        │  extracts facts / decisions / preferences / constraints as Zero Atoms
        ▼
  DedupEngine: Bloom filter → fingerprint candidates → similarity → polarity gate
        │
        ├─ new fact             → create
        ├─ same fact restated   → reinforce (bumps reinforcement_count)
        └─ contradicts a fact   → supersede (old atom flagged + decayed, never deleted)
        ▼
  CNSStore (SQLite, the frozen `cns_atom` / `cns_namespace_policy` schema)
```

Nothing in this path calls a model — that's the point. Distillation is regex/
heuristic-based on purpose: it can't introduce a claim the source didn't
make, because every atom's `object` text is a substring the pattern actually
captured. A host that wants richer, model-backed extraction can layer one in
front of this and hand ZeroFold the resulting atoms directly instead.

## Promotion and ROI

An atom starts `episodic` and decays on its TTL unless it earns `long_term`
status:

```
promote_to_long_term if:
    explicit_user_rule
    OR reinforcement_count >= promotion_reinforce_n   (default 2)
    OR (high_importance AND confirmed)
```

Every atom tracks what it cost to produce (`production_cost_tokens/usd`) and
what it has saved on reuse (`tokens_saved_total`, `retrieval_savings_usd`).
The first retrieval that pushes savings past production cost freezes
`payback_count` at that retrieval number — it is never rewritten afterward,
so you can always answer "how fast did this pay for itself" even if it keeps
getting used for years. `zerofold.cns.ledger.Ledger.namespace_health()`
reports both the average payback speed *and* the payback rate across a
namespace, because a namespace with a fast average but a low hit rate can be
worse than one with a slower average and a high rate — collapsing that to
one number hides the real signal.

## Fidelity: the "RelAi Race"

Compression is never trusted on the compressor's own word. `FidelityGate`
runs a free deterministic diff first (entities, numbers, dates, negations
must survive), and only then optionally asks an independent scorer — which
must not be the same model that produced the compression — for a fidelity
score. Below threshold, or if the deterministic diff fails outright, it
falls back to the raw text rather than shipping something uncertain:

```python
from zerofold import FidelityGate

gate = FidelityGate(threshold=0.8)
result = gate.evaluate(raw_text, compressed_text, independent_scorer=my_scorer)
# result.dispatch_text is what you actually send — compressed if it earned
# trust, raw otherwise.
```

## Complexity floor

```python
from zerofold import ComplexityInputs, complexity_score, min_quality_tier

score = complexity_score(ComplexityInputs(intent="code", context_tokens=6000))
tier = min_quality_tier(score)  # 1 (cheap) / 2 (mid) / 3 (premium)
```

Feed `tier` into your router as a floor: filter the candidate model pool to
`quality_tier >= tier`, *then* rank by price. This is what `ZeroSupervisor.intake()`
returns as `min_quality_tier`.

## Design tradeoffs (Day-One vs. scale-triggered)

The `cns_atom` schema (`zerofold/cns/schema.py`) is frozen — see `docs/spec.html`
section 8. Deliberately **not** in it: a fingerprint column, a vector index,
or anything else that would require a migration to add. Day-One dedup scans
a namespace's rows in Python and narrows with a Bloom filter + similarity
backend first; that's a documented tradeoff, not an oversight. Similarly,
similarity defaults to pure-Python TF-cosine (`zerofold.similarity.LocalTextSimilarity`)
rather than an embedding model, so installing ZeroFold never drags in a
model runtime. Both are one-line swaps — implement `SimilarityBackend` or
add an indexed column in a new migration — once actual scale demands it, not
before.

## Testing

```bash
pytest -q
```

101 tests cover every module: atom hashing/fingerprinting, the Zero Language
fold/unfold roundtrip, the Bloom filter's no-false-negatives guarantee, the
relevance gate, the distiller's pattern extraction, the fidelity gate's
RelAi Race (including retry and fallback paths), dedup's create/reinforce/
supersede decisions, the CNS store's atomic payback-crossing update, the
Ledger's promotion rules, the complexity floor, the output contract /
outbound validator, and a full lifecycle integration test (evict → reinforce
→ promote → context injection → outbound validation).
